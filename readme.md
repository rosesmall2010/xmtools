# xmtools

基于 **Node.js 24 LTS** + **TypeScript** 的命令行工具集合。

## 工程约定

- 根目录下每个 `.ts` 文件对应一个**工具命令**，由 TypeScript 编译为同目录下的 `.js` 文件。
- `lib/` 目录存放工具的**共有代码**，同样编译为同目录下的 `.js`。
- `config/` 目录存放工具所需的配置，采用 **yaml** 格式，配置文件名与工具名一致（如工具 `hello` 对应 `config/hello.yaml`）。
- 公共依赖：`xmcommon`（通用功能库）、`yaml`（配置解析）。

## 编译与运行

```bash
npm install     # 安装依赖
npm run build   # 编译 TypeScript（tsc，产物与源码同目录）
npm run watch   # 监听模式编译
node <工具名>.js   # 运行某个工具
```

## 工具列表

### hello

- **作用**：示例工具。读取 `config/hello.yaml` 中的 `greeting` 配置并打印问候语；配置缺失时输出默认值 `Hello, World!`。
- **启动方式**：`node hello.js`
- **启动参数**：无。

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `greeting` | 要打印的问候语 | `Hello, World!` |

### findequ

- **作用**：查找重复文件。递归扫描指定目录下所有文件，计算每个文件的 MD5，按 MD5 分组输出重复文件统计。
- **启动方式**：`node findequ.js <目录路径>`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<目录路径>` | 要扫描的目标目录（必填） |

- **输出**：处理过程中显示多行进度面板（当前文件、进度条、文件数、字节数、速度/耗时）；结果 JSON 保存到当前目录 `findequ-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "path": "扫描的目录绝对路径",
  "file": {
    "md5值": {
      "size": "文件大小（可读格式）",
      "count": "相同 md5 的文件数",
      "paths": ["相对路径1", "相对路径2", "..."]
    }
  },
  "total": {
    "fileCount": 文件总数,
    "totalSize": 文件总大小,
    "duplicateCount": 重复文件总数,
    "duplicateSize": 重复文件总大小,
    "md5Count": 有重复的 md5 个数
  }
}
```

- **示例**：`node findequ.js ~/Downloads`

### mvequ

- **作用**：读取 `findequ` 的结果 JSON，对每组重复文件（同一 MD5、count > 1），保留第一个文件在原处，其余的按相对路径**移动**（非复制）到目标目录，保持原有目录结构。
- **启动方式**：`node mvequ.js <findequ-result.json> <目标目录>`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<findequ-result.json>` | `findequ` 输出的结果文件路径（必填） |
| `<目标目录>` | 重复文件移动到的目标目录（必填） |

- **行为说明**：源文件不存在或目标位置已存在同名文件时跳过并警告；跨设备移动失败时自动退化为复制后删除源文件。
- **输出**：处理结果保存到当前目录 `mvequ-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "source": "findequ 结果中的源目录",
  "target": "目标目录绝对路径",
  "moved": ["已移动的相对路径", "..."],
  "skipped": [
    { "path": "相对路径", "reason": "跳过原因（源文件不存在 / 目标已存在 / 移动失败: ...）" }
  ],
  "total": { "movedCount": 已移动文件数, "skippedCount": 跳过文件数 }
}
```

- **示例**：`node mvequ.js findequ-result-123.json /data/dup-out`

### renametag

- **作用**：修正文件名（均只作用于文件名本身，不含路径、不含扩展名）。递归扫描目录下所有文件。
  - 数字前缀：`数字.中间名.扩展名` → `中间名.数字.扩展名`（如 `13456.AAA.mp3` → `AAA.13456.mp3`）；若只有"数字.扩展名"两段（如 `12345.mp3`），不处理。
  - `3D`/`3 D` 前缀：紧贴文件名开头（无需点分隔）→ 移到扩展名前（如 `3DAAA.mp3` → `AAA.3D.mp3`）。
  - 连字符规范化：连续多个 `-`（中间可有空格，如 `- -`）先合并成一个 `-`，再统一改成 `" - "`（如 `张三-AAA.mp3` → `张三 - AAA.mp3`；`张三- -AAA.mp3` → `张三 - AAA.mp3`）。
- **启动方式**：`node renametag.js <目录路径>`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<目录路径>` | 要处理的目标目录（必填） |

- **行为说明**：改名后若目标文件名已存在，在扩展名前插入一个编号再试（如 `张三 - AAA.mp3` 已存在 → `张三 - AAA.9.mp3`）。编号从 1 开始，在本次运行中每使用一次（无论是否成功）就 +1、不会重复使用，仍冲突则继续用下一个编号重试，直到文件名不冲突为止。
- **输出**：处理结果保存到当前目录 `renametag-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "path": "扫描的目录绝对路径",
  "renamed": [{ "from": "原相对路径", "to": "新相对路径" }],
  "skipped": [{ "path": "相对路径", "reason": "跳过原因（重命名失败: ...）" }],
  "total": { "renamedCount": 已重命名文件数, "skippedCount": 跳过文件数 }
}
```

- **示例**：`node renametag.js ~/Music`

### rmemptydir

- **作用**：递归删除指定目录下所有的空子目录（目标目录本身不删除）。自底向上级联：子目录被删除后若父目录因此变空，父目录也会被删除，直到不再产生新的空目录为止。
- **启动方式**：`node rmemptydir.js <目录路径>`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<目录路径>` | 要清理的目标目录（必填），目标目录本身不会被删除 |

- **行为说明**：文件、符号链接均视为"非空"，含有它们的目录及其祖先目录不会被删除。
- **输出**：处理结果保存到当前目录 `rmemptydir-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "path": "扫描的目录绝对路径",
  "removed": ["被删除的空目录相对路径", "..."],
  "skipped": [{ "path": "相对路径", "reason": "跳过原因（读取目录失败: ... / 删除失败: ...）" }],
  "total": { "removedCount": 已删除目录数, "skippedCount": 跳过数 }
}
```

- **示例**：`node rmemptydir.js /data/music`

### mvflat

- **作用**：递归把源目录下指定扩展名的文件移动到目标目录，不保留相对路径（拍平）。是移动而非复制，源文件会被删除；移动后源目录下可能残留空子目录，可配合 `rmemptydir` 清理。
- **启动方式**：`node mvflat.js <源目录> <目标目录> <扩展名>`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<源目录>` | 要扫描的源目录（必填） |
| `<目标目录>` | 存放文件的目标目录（必填），不存在时自动创建 |
| `<扩展名>` | 只匹配文件名最后一个点之后的部分，大小写不敏感，可带或不带前导点（如 `mp3` / `.mp3`）；传 `*` 表示不筛选，移动所有文件（含没有扩展名的文件）。在 shell 中使用 `*` 时需加引号（`'*'`），否则会被 shell 展开成当前目录的文件名 |

- **行为说明**：目标目录已存在同名文件时（重名冲突），做法与 `renametag` 一致——在扩展名前插入一个编号再试，编号从 1 开始，每使用一次（无论是否成功）就 +1，在本次运行中递增、不会重复使用，仍冲突则继续用下一个编号重试，直到文件名不冲突为止。
- **输出**：处理结果保存到当前目录 `mvflat-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "source": "源目录绝对路径",
  "target": "目标目录绝对路径",
  "ext": "筛选的扩展名（小写，* 表示全部）",
  "moved": [{ "from": "源相对路径", "to": "目标目录下的新文件名" }],
  "skipped": [{ "path": "相对路径", "reason": "跳过原因（移动失败: ...）" }],
  "total": { "movedCount": 已移动文件数, "skippedCount": 跳过文件数 }
}
```

- **示例**：`node mvflat.js /data/music /data/music-flat mp3`

### mp3info

- **作用**：递归扫描目录下所有 `.mp3` 文件，提取 ID3 标签与音频参数；带 `--update` 时把非 UTF-8 的标签重写为 ID3v2.4 + UTF-8。
- **启动方式**：`node mp3info.js <目录路径> [--update]`
- **启动参数**：

| 参数 | 说明 |
| --- | --- |
| `<目录路径>` | 要扫描的目标目录（必填），递归处理所有子目录 |
| `--update` | 可选开关。把有变化的标签**写回文件**（默认关闭，只扫描输出，不修改文件）。放在目录路径前或后均可 |

- **提取信息**：
  - 文件：文件名、相对路径、文件大小
  - ID3 标签：歌手（`TPE1`）、歌曲名（`TIT2`）、专辑（`TALB`）、年份（`TYER`/`TDRC`）、流派（`TCON`），并标注每个字段的原始编码（`utf8` / `utf16` / `gbk` / `latin1乱码还原` / `big5乱码还原`）
  - 音频参数：码率（VBR 会标注）、时长、采样率、声道（单声道/立体声/联合立体声/双声道）
- **编码检测**：ID3v2 文本帧自带编码标识（0=ISO-8859-1、1=UTF-16 带 BOM、2=UTF-16BE、3=UTF-8），但大量历史中文标签虽声明 0 实际写入的是 GBK/GB2312 字节。工具对非 ASCII 内容先按严格 UTF-8 解码，失败则退回 GB18030（兼容 GBK/GB2312）；若 GB18030 结果仍是「GBK 字节被当 ISO-8859-1」的乱码（如 `Îé°Û`），再按 GB18030 还原一次。无 ID3v2 标签时读取文件末尾 128 字节的 ID3v1 兜底（同样按 GB18030 解码）。
  - Big5（繁体）还原：部分台湾/香港打标工具写入的是 Big5 字节。Big5 与 GBK 的字节空间完全重叠，单看字节无法区分，因此只在文本已呈现乱码特征（含控制符/私有区字符，或 CJK 兼容形式、注音符号、CJK 兼容汉字）时，才尝试把它按 Big5 反查还原；未能唯一还原或还原结果仍可疑则保持原样。
  - 说明：源字节本身已被破坏的乱码（含控制字符/私有区字符，无法还原）保持原样输出，不做臆测性替换。
- **字段长度限制**：歌手、歌曲名、专辑、年份、流派五个字段各最多保留 **50 个字符**，超出部分按 Unicode 码点截取（不会截断成半个字符）。**注意**：截断只作用于输出的 JSON（`title` 等字段），`--update` 写回用的是**未截断**的原文，不会把长标签截掉。
- **`--update` 写回**：
  - **判据**：任一非空字段的原始编码不是 `utf8`（即 `utf16` / `gbk` / `latin1乱码还原` / `big5乱码还原`）→ 该文件需要写回。字段全为空或已是 UTF-8 的文件不动。
  - **保留其余帧**：只重建需要转码的文本帧（`T*` / `TXXX` / `COMM`）与 v2.4 已废弃的日期帧；**封面（`APIC`）、歌词（`USLT`）、`TRCK`、`TPE2` 等其余帧按原字节原样保留**，不会丢失。帧区变短时补 0 保持原长度；转码后变长时不裁剪（一个帧都不丢），此时音频数据整体后移。
  - **ID3v2.2**：v2.2 的 3 字符帧 ID（`TT2` / `TP1` / `PIC` 等）在读取时就映射为 v2.3/2.4 的 4 字符 ID 并补齐帧头，写回后是规范的 v2.4 帧；未收录的 v2.2 帧丢弃。
  - **写回格式**：标签升级为 **ID3v2.4 + UTF-8**（编码字节 3）。年份统一写 `TDRC`（v2.4 已废弃 `TYER`）；`TXXX` 保留描述字段；`COMM` 保留原语言码。
  - **ID3v1**：只有 ID3v1 标签的文件升级为 ID3v2.4（原字段转为对应的 v2 帧），并**删除**文件末尾旧的 128 字节 `TAG` 块，避免新旧两套标签并存。完全没有标签的文件跳过（无数据可更）。
  - **不备份**：先写临时文件再 `rename` 原子覆盖，写失败则原文件不受影响；不额外保留 `.bak`。
  - 写回是幂等的：对同一目录再跑一次 `--update`，`changedCount` 为 0，文件不会被再次改写。
- **进度与汇总**：处理过程显示多行进度面板（当前文件、进度条、文件数、耗时）；结果 JSON 末尾 `total` 含汇总：扫描/跳过/无 ID3 标签数、**ID3 变化/未变化数**、总时长、VBR 数、各原始编码的字段数。
- **输出**：处理结果保存到当前目录 `mp3info-result-<时间戳>.json`，只打印保存路径，不打印内容。

结果 JSON 结构：

```json
{
  "path": "扫描的目录绝对路径",
  "files": [
    {
      "name": "文件名",
      "path": "相对路径",
      "size": "文件大小（可读格式）",
      "id3Version": "ID3v2.3 / ID3v1 / 无（--update 写回后为 ID3v2.4）",
      "id3Changed": "ID3 是否有变化（--update 时为「已写回」，否则为「需要写回」的预告）",
      "title": "歌曲名",
      "titleEnc": "该字段原始编码（utf8 / utf16 / gbk / latin1乱码还原 / big5乱码还原）",
      "artist": "歌手",
      "artistEnc": "同上",
      "album": "专辑",
      "albumEnc": "同上",
      "year": "年份",
      "yearEnc": "同上",
      "genre": "流派",
      "genreEnc": "同上",
      "bitrate": "码率（如 128 kbps，VBR 加标注）",
      "duration": "时长（mm:ss）",
      "sampleRate": "采样率（如 44100 Hz）",
      "channel": "声道"
    }
  ],
  "skipped": [{ "path": "相对路径", "reason": "跳过原因（读取失败 / 未识别到合法的 MPEG 音频帧）" }],
  "noTags": [{ "path": "相对路径", "id3Version": "无" }],
  "total": {
    "fileCount": 成功扫描数,
    "skippedCount": 跳过数,
    "noTagCount": 无 ID3 标签文件数,
    "changedCount": "ID3 有变化的文件数（--update 时即实际写回数）",
    "unchangedCount": "ID3 未变化的文件数",
    "totalDuration": "总时长（mm:ss）",
    "vbrCount": VBR 文件数,
    "encCount": { "各原始编码": 字段数 }
  }
}
```

- **示例**：`node mp3info.js ~/Music`；`node mp3info.js ~/Music --update`
